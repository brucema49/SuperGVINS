# SuperGVINS 整体规划：将 SuperVINS 的 LightGlue 前端接入 GVINS

> 初版 2026-11-18，校正于 2026-11-20。实施记录见 [11-18 前端替换日志](../issue/11-18前端替换日志.md)。勾选项只代表其所述范围已有证据。

## 1. 目标与确定约束

参考 `src/SuperVINS` 当前的 SuperPoint + LightGlue 前端实现，以 `src/GVINS` 当前代码为后端基础，在 `src/SuperGVINS` 中形成视觉、IMU、GNSS 紧耦合定位工程。

**帧处理规则已确定：前端使用全部图像数据帧，后端依然采用隔帧处理。** 前端逐帧提取、逐帧匹配、逐帧更新轨迹并发布特征结果；后端保留 GVINS 的隔帧选择及 GNSS 时间对齐逻辑。不得同时在前端和后端各做一次隔帧。

**架构：**采用独立学习前端节点，通过 GVINS 现有 `sensor_msgs/PointCloud` 特征协议连接后端。保持 GVINS 的视觉惯性初始化、滑窗优化、GNSS 原始观测融合、时间同步及坐标输出含义，先实现接口等价，再评估学习前端带来的变化。

**特征预算已确定：每个合法图像帧只调用一次 SuperPoint；原始检测数允许超过 512，按检测质量保留至多 512 个关键点及对应描述子；有效一一匹配点对和最终保留轨迹均不超过 128。** 复用前帧缓存，不为补点、匹配或可视化重复提取，不以 128 点替代当前帧的 512 点候选集。

**测试与交付路径已确定：**使用 `data/gvins/sports_field.bag`；运行结果、日志、配置快照、统计与 SuperGVINS/GVINS 轨迹对比图全部保存到 `output/supergvins/`。先完成正常退出和短窗口联调，再做前 600 秒对照与完整 bag 验收。所有窗口均采用前端全帧、后端隔帧。

**技术栈：**ROS1、catkin、C++14、OpenCV、Eigen、Ceres、camodocal 相机模型、ONNX Runtime、SuperPoint、LightGlue、gnss_comm、Python/NumPy/Matplotlib 轨迹评估。

本阶段范围：

- 单目相机 + IMU + GNSS；与 GVINS 当前 `NUM_OF_CAM = 1` 保持一致。
- 学习前端替换传统角点检测与 LK 跟踪，保留必要的几何验证、轨迹管理和相机反投影。
- 提供 CPU 可验证路径，再验证目标设备上的 CUDA 执行。
- 保留原始 GVINS 作为对照，新增工程使用独立包名、节点名、配置和输出目录。

本阶段不纳入双目扩展、回环、模型训练、模型重新导出、GNSS 因子重写及 SuperVINS 整套估计器迁移。后续实施按第 7 节给出的剩余任务依赖推进。

## 3. 迁移路线与取舍

| 路线 | 收益 | 代价与结论 |
| --- | --- | --- |
| 独立学习前端 + GVINS 消息接口 | 前后端边界清楚，可直接验证协议及帧率，保留 GNSS 后端 | 需要消息适配；作为本规划采用路线 |
| 将学习前端嵌入 GVINS 估计器 | 减少消息传递 | 需改变线程、缓存及生命周期，扩大改动范围，本阶段不采用 |
| 向 SuperVINS 估计器移植 GNSS | 可直接使用原学习前端调用链 | 需迁移 GNSS 初始化、因子及同步机制，偏离以 GVINS 为基础的目标，本阶段不采用 |

采用路线的数据流：

```text
全部相机图像帧（保留采集时间戳）
  → 灰度转换与模型预处理
  → 每帧一次 SuperPoint 推理，按检测分数保留 top-512
  → 缓存前帧至多 128 点 × 当前帧至多 512 点的 LightGlue 匹配
  → 至多 128 对有效匹配、几何筛选、ID 继承与已有候选补点
  → 最终保留至多 128 条轨迹及自有描述子，供下一帧复用
  → 相机反投影与归一化平面速度
  → 每帧发布 PointCloud 特征消息
  → GVINS feature_callback 隔帧选择与原有时间对齐
  → IMU 积分 + GNSS 观测 + 滑窗优化
  → GVINS 原有语义的轨迹与全局定位输出
```

“端到端前端”在本文指学习特征提取与学习匹配组成完整视觉前端，不表示已存在单个“输入双图直接输出轨迹”的模型。当前参考实现分别加载提取器和匹配器；模型文件名含 `fused` 不能替代对输入输出签名的检查。

## 5. 前后端协议与帧处理规则

### 5.1 每帧特征消息

新前端发布 `/supergvins_feature_tracker/feature`，类型为 `sensor_msgs/PointCloud`；后端目前直接订阅该话题。接入原 GVINS 前端做对照时，在 launch 中显式 remap 特征和重启话题。

| 字段 | 必须保持的语义 |
| --- | --- |
| `header.stamp` | 当前输入图像采集时间，不使用推理完成时间或 `ros::Time::now()` |
| `header.frame_id` | 首期保持 GVINS 前端使用的 `world` 字符串兼容约定；points 实际为相机归一化坐标，不能当作世界三维点解释 |
| `points[i]` | 相机模型反投影后的 `(x_normalized, y_normalized, 1)` |
| `channels[0].values[i]` | `feature_id * NUM_OF_CAM + camera_id`，单目 camera_id 为 0 |
| `channels[1].values[i]` | 原始图像像素坐标 u |
| `channels[2].values[i]` | 原始图像像素坐标 v |
| `channels[3].values[i]` | 归一化平面速度 vx，单位为每秒 |
| `channels[4].values[i]` | 归一化平面速度 vy，单位为每秒 |

通道顺序固定，所有通道长度必须等于 points 数量，坐标与速度均为有限值，ID 在同一帧唯一。可填通道名称用于诊断，但兼容性以 GVINS 当前读取的下标顺序为准。

现有节点按同一条轨迹填充五个通道，使用该轨迹的 age 判断成熟度。5 帧短测已核对通道长度、时间戳和持续轨迹速度。后续在后端入口验证非法通道长度、非有限值和重复 ID，避免解析时越界。

### 5.2 全帧前端与隔帧后端

- 移除新前端的 `PUB_THIS_FRAME`、`pub_count` 频率门控及首次发布跳过逻辑；不得仅通过设置 `freq = 0` 实现全帧处理，也不迁入 SuperVINS 的 `backend_frame_stride` 门控。
- 每个合法输入帧都且仅执行一次 SuperPoint 推理；有有效前帧时使用其缓存描述子匹配，不重新提取前帧。前端保留每帧的描述子、轨迹和时间，不因该帧稍后被后端跳过而省略计算。
- 保持 GVINS 的成熟点约定：track_cnt > 1 的点进入观测。首帧、新点尚未成熟帧或确无有效轨迹帧仍发布该图像时间戳对应的空特征消息，作为帧序列的一部分；推理失败另按异常策略处理，不能伪装成正常空结果。
- 后端 `feature_callback()` 保留基于 `feature_msg_counter` 和 `skip_parameter` 的隔帧处理。GNSS 开启时，保留当前等待时间差有效、根据邻近 GNSS 时刻确定奇偶相位的规则，不简化成固定取偶数帧。
- GNSS 关闭时继续隔帧；初始空观测参与消息计数，但不送入 `processImage()`。真实运行中若选中帧无有效观测，同样跳过视觉更新并记录原因，不额外补选相邻帧。
- 前端速度由同 ID 相邻有效跟踪帧计算：`v = (un_current - un_previous) / (t_current - t_previous)`。后端虽然隔帧更新，也不得将速度除以两帧时间或对其重复缩放。
- 统计区分收到图像数、完成前端数、发布消息数、后端回调数、入队数与实际优化数。启动同步等待、空观测和异常造成的减少单独列出。

验收示例：20 Hz 图像在处理能力足够时应产生约 20 Hz 前端结果；同步稳定且观测有效时后端入队约 10 Hz。若有 N 帧正常输入，前端完成数与发布数均为 N；后端稳定阶段按原相位选中的消息数应与半帧率规则一致，不能出现约 N/4 的重复降采样。

### 5.3 坐标、匹配与轨迹状态

- SuperPoint 预处理保留参考实现的灰度、浮点归一化、长边缩放和插值约定。模型图像尺寸、原图尺寸及缩放元数据显式保存；复用 `(p + 0.5) / scale - 0.5` 时以非方形图验证取整误差，若调整为实际宽高比例需同步校验模型坐标约定。
- 区分三种坐标：原图像素、LightGlue 内部关键点归一化坐标、相机反投影归一化平面坐标；后两者不得混用。畸变相机必须通过 GVINS 所用相机模型 liftProjective 后再除以 z。
- 匹配输出检查数量、类型、shape、索引范围与有限值；padding 点不得进入有效轨迹，同一当前点不得继承多个 ID。参考 matcher 当前使用严格 `score > threshold`，配置阈值不得设为会筛空全部合法分数的 1.0。
- 几何筛选沿用参考实现并核实其坐标域及阈值单位。匹配不足以估计几何模型时给出明确退化结果，不使用未初始化的内点 mask。
- 成功匹配继承 ID 并增加 track_cnt；未匹配点分配新 ID；出界、失配及被剔除点的坐标、ID、计数和描述子同步处理。新点速度置零，成熟后才进入有效观测。
- ID 编码使用 float32 通道，编码整数必须保持精确可表示，达到 `2^24` 前触发协调重启，禁止无提示溢出或在同一后端生命周期内复用 ID。

### 5.4 单次提取、512 候选与 128 匹配预算

参照 `eval_k512_r128` 对应的运行配置与源码，具体执行顺序如下：

1. 对当前帧执行一次 SuperPoint，取得原始 `keypoints/scores/descriptors`，记录 `raw_keypoints`。模型输出 513、872 或更多点均允许，512 是输出后保留上限，不要求模型只检测 512 点。
2. 若原始点数超过 512，按 SuperPoint 检测分数降序选择 top-512；同分按原始索引升序打破平局。关键点、分数、256 维描述子使用同一索引重排。点数不足时全部保留，不补造特征。参考 `Extractor_DPL::post_process()` 的 `partial_sort` 及描述子复制逻辑。
3. 图像边界/掩膜过滤后，以当前帧至多 512 个候选，与上帧已保留的至多 128 条轨迹匹配；复用缓存中的前帧描述子与坐标。首帧只提取并建立至多 128 个初始轨迹，无需匹配。
4. LightGlue 使用有效索引、分数阈值、去 padding 及一一对应检查。因前帧集合至多 128 点，有效唯一匹配数自然不超过 128，RANSAC 后数量同样不超过 128；另加显式预算断言/保护，不能仅在发布消息时裁剪来掩盖超限。
5. 成功匹配的长轨迹优先放入保留列表，随后从**本帧已经提取的候选集**中按空间间隔补充新点，按参考实现顺序截断到 128。匹配点数与最终轨迹数分开记录；不足 128 时不重复提取或伪造匹配。
6. 缓存最终至多 128 条轨迹及自有描述子供下一帧使用；当前帧用于匹配的 512 候选不能在 LightGlue 前就裁成 128。成熟轨迹进入消息，故每帧观测数也不超过 128。

参考运行日志核对结果：`output/supervins_compare/sportfield/supervins_k512_r128/experiment/raw/estimator_428133/inference.csv` 的有效 extractor 记录共 11983 条，同一 `(epoch, frame_id, stamp_ns)` 最多一次提取，原始输出最多 872 点、保留输出最多 512 点；matcher 输出/有效匹配及 frames.csv 中保留数最多 128。它是设计参考，不代表新工程已经通过验证，也不能用轨迹行数推断前端是否全帧。

参考 YAML 的 `retained_target_features: 128` 使实际保留上限为 128。新工程在 `learned_frontend.cpp` 直接固定 128 上限。`matcher_min_kpts: 128` 是 padding 下限，不是匹配对数限制；上限必须由前帧有效集合和匹配验证保证。参考的 `backend_frame_stride: 1` 不迁入本工程，后端仍按第 5.2 节隔帧。

现有 `frontend_frames.csv` 以 `frame_id,stamp_ns` 为键逐帧记录 `superpoint_calls`、`raw_keypoints`、`kept_keypoints`、`prev_track_count`、`matcher_raw_pairs`、`matches_before_ransac`、`matches_after_ransac`、`retained_tracks` 与 `published_points`，并记录 `extract_ms`、`match_ms`、`total_ms`。运行 ID 由输出目录与 `run.json` 关联，加入重启隔离时补充世代编号及拒绝原因。正常帧断言 `superpoint_calls == 1`、`kept_keypoints <= 512`，前帧轨迹、有效匹配对、最终保留和发布数均 `<= 128`，并对原始 matcher 点对的唯一性及范围做独立校验。帧率规则与特征数量预算分别验收。

### 5.5 异常、重启与数据完整性

- 图像重复时间戳、倒退时间戳、超过现有 1 秒断流阈值以及实际尺寸与标定不符时，明确记录原因；时间异常清空跟踪状态并通知后端，尺寸错误拒绝处理，禁止产生非有限速度。
- 正常无匹配属于可恢复情况，当前帧作为重新建轨起点；模型加载失败、签名不符、推理异常属于错误，停止本轮回放并保留诊断，不静默退回 LK 或丢帧继续声称全帧处理。
- 当前 reset 清除前帧轨迹与时间，ID 保持单调。后续实现跨节点重启确认和世代隔离，确保清理缓存与在途批次完成后才接受新轨迹。保留当前 ID 分配方式。
- GVINS 当前 restart 回调只清空部分缓存与估计器状态。新工程须核对正在处理的批次、GNSS 缓存、同步状态、feature_msg_counter、skip_parameter 与重启的配合，避免旧批次在 reset 后进入新窗口；保留 GNSS 奇偶相位选择的规则。
- “全部数据帧”以输入 bag 的合法图像序列为核对依据，ROS 订阅队列丢失也视为不满足约束。CPU 过慢时降低 bag 回放倍率，等待处理排空；实时输入需优化算力或使用有界缓存并报告溢出，不用主动抽帧掩盖吞吐不足。

### 8.3 两路轨迹统一、对齐与绘图

新增 `src/SuperGVINS/tools/compare_trajectories.py`，复用参考脚本的时间关联与绘图思路，改为独立的 SuperGVINS/GVINS 两路输入，去掉强制 VINS-Mono 输入及写死的 bag 起点/600 秒上限。

2. 记录各自完整覆盖区间与样本数；评估采用两路有效区间交集和同一 bag 相对时间。以最近时间戳、最大差 `0.05 s` 做一一关联，不跨缺口插值，不对不足覆盖的后段外推；关联数、拒绝数和时间差分布进入 summary。
3. 输出 `traj_compare_raw_xy.png` 展示原始坐标，保留漂移和原点/朝向差异。再以 **GVINS 为参考**对 SuperGVINS 做 SE(3) 刚体对齐，尺度固定为 1，输出 `traj_compare_xy.png` 与 `traj_compare_xyz.png`。图中分别标注系统、坐标单位、窗口、对齐方式和起终点，XY 使用等比例坐标。
4. 导出对齐后的完整位姿时同时旋转四元数，不能只改位置保留原姿态。若计算 Sim(3) 尺度，仅写入摘要做尺度差异诊断，不用于主图修正。
5. `trajectory_difference.csv` 记录关联时间与对齐后的 XYZ 差及欧氏距离；summary 汇总持续时长、路径长度、样本频率、初始化时间、轨迹差异分位数和重启/丢帧数。GVINS 是对照估计器，结果标为“两套估计轨迹的差异”，不将其称为真值 ATE 或精度提升证据。
6. `gnss_result.csv` 为全局融合诊断，ECEF 坐标不可直接叠加本地 world 轨迹。如补充全球轨迹图，两套系统必须使用同一固定 ECEF→ENU 原点及转换，分别标明与主对比的区别。

参考目录只借用做法，不要求复制其已生成图片。必须从本次两套系统的新原始结果重新生成三张图、TUM 文件和 summary，并保证图片有有效轨迹而非空白或仅有一条曲线。

## 9. 风险与处理顺序

| 风险 | 可观察症状 | 处理措施 |
| --- | --- | --- |
| 补点或匹配重复提取 | 同一帧出现多个 extractor 调用 | 只对当前帧运行一次 SuperPoint，缓存前帧描述子，补点复用当前 top-512 |
| 512/128 含义混淆 | 原始点超 512 被误判，或只在发布时裁到 128 | 单独记录原始/保留/匹配数，按第 5.4 节限制有效集合及一一匹配 |
| 轨迹格式/坐标错配 | 时间差巨大、姿态错误或 ECEF 与 world 混画 | 统一纳秒时间、四元数顺序与坐标系后再比较 |
| 前端再次隔帧或发布限频 | 前端数少于输入数，后端降到四分之一 | 删除前端门控，用输入时间戳与各阶段计数核对 |
| 联合运行退出异常 | 停止阶段出现 `terminate called without an active exception` | 按 P3 复现工作线程未回收，核对唤醒、join 和退出码 |
| 起播首帧未送达 | 首个相机时间戳缺失，后续连续 | 使用 `--delay 2`，对照 bag 索引确认首帧和整段覆盖 |
| CPU 推理积压 | 0.5 倍速下结束后仍有未处理帧 | 用 CUDA 短测选定可持续倍率，再验证长窗口及排空 |
| 短测未初始化 | 前端 40/40，但两份轨迹 CSV 为空 | 增加初始化联调窗口并验证同步、位姿输出和覆盖 |
| 坐标域或速度单位错误 | 重投影异常、初始化失败、轨迹突跳 | 优先执行缩放/相机反投影/速度协议测试，暂不调 GNSS 参数 |
| 阈值或 padding 导致匹配稀疏 | 提取点多、有效匹配近零 | 核查严格比较、有效索引与模型形状，再调整阈值 |
| 深拷贝或内存生命周期错误 | 下一次推理后描述子损坏、随机崩溃 | 保存跨帧自有描述子，覆盖连续多帧及会话释放测试 |
| 包或消息重名、库加载错误 | catkin 冲突、消息连接失败、运行找不到 ORT | 独立包命名，复用原触发消息，记录实际库与设备 |
| reset 时旧数据进入新窗口 | 重启后混入旧 ID、时间对齐失效 | 协调前后端重启确认，隔离在途批次并验证同步状态 |
| 对照参数不一致 | 无法判断差异来自前端还是标定/频率 | 固定设备参数、数据与后端选择规则，单独记录前端差异 |
